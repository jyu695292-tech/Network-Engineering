## 1 整体网络架构逻辑设计

### 1.1 三层架构总体逻辑拓扑

本项目采用标准三层园区网架构，分为**核心层、区域汇聚层、楼栋接入层**，无线部分采用AC旁挂+Fit AP瘦AP架构。

逻辑数据流：
终端 → 宿舍AP → 楼层POE接入交换机 → 区域汇聚交换机 → 核心交换机 → 出口防火墙/路由器 → 互联网

### 1.2 核心层职能设计

核心层部署在学校中心机房，是全网高速转发核心：
1. 全网三层路由转发核心，OSPF Area 0骨干区域节点。
2. 全部业务VLAN、管理VLAN的三层网关终结点，部署DHCP全局地址池。
3. 东区、西区、中区、新区四大片区流量汇聚、调度。
4. 对接出口防火墙安全设备。
5. 旁挂AC无线控制器，实现全网瘦AP集中管控。
6. 部署ACL策略，实现片区之间访问控制。

### 1.3 区域汇聚层职能设计

四大片区各部署一台区域汇聚交换机：
1. 收敛本片区所有楼栋接入交换机上行流量。
2. Trunk透传本片区全部业务VLAN、管理VLAN，不做三层网关。
3. 作为OSPF的区域节点，与核心建立OSPF邻居。
4. 配置Eth‑Trunk链路聚合，提供链路冗余、负载分担。
5. 处理本片区二层环路抑制，STP根桥备份。

### 1.4 楼栋接入层职能设计

每栋宿舍楼部署POE接入交换机：
1. 为室内Fit‑AP提供POE供电。
2. 接入端口划分对应楼栋业务VLAN，上行Trunk透传业务VLAN+管理VLAN。
3. 接入安全：DHCP‑Snooping、ARP防护、端口MAC‑Limit，防止私接路由、ARP欺骗。
4. STP生成树，防止二层环路。
5. 双上行链路到汇聚交换机，实现链路冗余。

## 2 VLAN与IP地址规划

> 设计原则
> 1. **业务VLAN：按楼栋划分，一栋楼一个独立业务VLAN**，缩小广播域，广播风暴限制在单栋楼内部。
> 2. **管理VLAN独立隔离**：所有交换机、AP设备管理地址统一放在管理VLAN，不和学生业务网段混合。
> 3. 网关全部终结在核心交换机VLANIF接口，汇聚、接入只做二层透传。
> 4. 网段连续规整，方便OSPF宣告、ACL策略编写、后期扩容。
> 5. 每个业务网段使用`/24`子网，单网段最大容纳254台终端，适配一栋宿舍终端规模。

### 2.1 VLAN规划详细说明

| VLAN用途           | VLAN ID范围 | 说明                                           |
| ------------------ | ----------- | ---------------------------------------------- |
| 东区宿舍楼业务VLAN | 1001‑1130   | 东区共130栋宿舍楼，每栋楼占用1个VLAN           |
| 西区宿舍楼业务VLAN | 2001‑2120   | 西区共120栋宿舍楼，每栋楼占用1个VLAN           |
| 中区宿舍楼业务VLAN | 3001‑3020   | 中区共20栋宿舍楼，每栋楼占用1个VLAN            |
| 新区宿舍楼业务VLAN | 4001‑4070   | 新区共70栋宿舍楼，每栋楼占用1个VLAN            |
| 全网设备管理VLAN   | 999         | 交换机、AC、AP设备管理网段，不承载学生业务流量 |
| DMZ服务器区VLAN    | 888         | Portal服务器、Radius认证服务器、日志审计服务器 |

> VLAN部署规则
1. 接入交换机：接AP的access端口划入对应楼栋业务VLAN；上行端口配置Trunk，允许**本片区业务VLAN + VLAN999**通过。
2. 汇聚交换机上行Trunk：透传本片区全部业务VLAN + VLAN999 + VLAN888。
3. 核心交换机：为每一个VLAN配置VLANIF三层接口，作为该网段默认网关。
4. 禁止业务端口配置VLAN999，防止学生终端闯入设备管理网段。

> 示例：东区1号宿舍楼
- VLANID：1001
- 接入交换机AP端口 Access VLAN 1001
- 上行Trunk允许VLAN1001，VLAN999通过
- 核心创建VLANIF1001，作为该楼栋网关。

### 2.3 DHCP服务逻辑详细设计
DHCP部署在核心交换机，全局地址池模式，分为**业务地址池**与**设备管理地址池**。

1. **业务地址池**
    - 每一栋楼对应一个独立DHCP地址池，和VLANIF一一对应。
    - 网关：为本VLANIF接口IP。
    - 子网掩码：255.255.255.0
    - DNS：校园内网DNS + 公共DNS。
    - 租期：8小时，学生终端流动性高，缩短租期方便IP回收。
    - 排除网段：每个网段前1‑10地址预留，用于静态网关、后期服务器。

2. **设备管理地址池（VLAN999）**
    - 只为交换机、AP分配管理IP，**禁止学生终端获取该网段地址**。
    - DHCP Option43配置AC控制器IP，AP获取地址后自动发现AC。

3. DHCP安全防护
    - 所有接入交换机开启`dhcp snooping`，上行Trunk口配置trust，接入端口untrust。
    - 拒绝私接DHCP服务器，防止内网IP欺骗。
    - 配合ARP‑anti‑gateway防护，防止ARP网关欺骗。

## 3 路由协议设计

### 3.1 内网路由协议选型
内网采用OSPF动态路由协议。
1. 标准公有协议，华为设备原生支持。
2. 支持等价路由，双上行链路负载分担。
3. 链路故障自动收敛，无需人工修改静态路由。
4. 适合中型园区，方便后期楼栋扩容。

### 3.2 OSPF区域划分逻辑
全网单骨干Area 0，所有三层设备全部加入Area 0。
1. 核心交换机：OSPF骨干节点
    - Core‑A Router‑ID：`1.1.1.1`
    - Core‑B Router‑ID：`1.1.1.2`
2. 四台汇聚交换机Router‑ID分别为：2.2.2.1、2.2.2.2、2.2.2.3、2.2.2.4。
3. 宣告网段：**所有业务网段10.10.0.0/16、10.20.0.0/16、10.30.0.0/16、10.40.0.0/16，管理网段192.168.99.0/24，DMZ 192.168.88.0/24全部宣告进OSPF**。
4. 接入交换机对接的终端端口配置为`silent‑interface`被动接口，不发送OSPF报文，避免终端收到路由报文。

### 3.3 出口路由逻辑
1. 核心交换机配置默认静态路由`0.0.0.0/0`，下一跳指向防火墙内网接口。
2. 防火墙配置回程静态路由，把四个业务大网段、管理网段指向核心交换机。
3. 防火墙做源NAT，内网学生网段转换为公网地址访问互联网。

### 3.4 路由冗余与收敛机制
1. 接入交换机双链路上联两台汇聚，STP实现二层冗余，故障自动切换。
2. OSPF收敛时间＜10s，链路故障自动重新计算路径。
3. 核心双设备，VRRP做网关冗余，单台核心故障，三层网关不中断。

## 4 无线网络逻辑设计

### 4.1 无线架构选型
采用**AC旁挂核心 + Fit AP瘦AP**。
1. AP零配置，上电DHCP获取管理IP，通过Option43发现AC。
2. AC统一管理所有AP，批量下发配置、版本升级。
3. 支持二层、三层漫游，负载均衡，射频自动优化。

### 4.2 AC管理逻辑
1. AC旁挂核心交换机，CAPWAP隧道管理AP。
2. AP管理流量走VLAN999管理网段；学生业务流量本地转发（AP本地转发模式），业务流量不经过AC，减轻AC压力。
3. 所有射频、SSID、Portal认证策略由AC统一下发。

### 4.3 漫游逻辑
1. 同楼栋二层漫游：终端IP不变，切换时延＜50ms。
2. 跨楼栋三层漫游：AC处理三层漫游，业务会话不中断。
3. 漫游触发阈值：终端信号低于‑75dBm触发漫游。

### 4.4 射频优化逻辑
1. AC自动信道规划，2.4G 1、6、11非重叠信道。
2. 自动功率调节，避免AP之间信号互相干扰。
3. 负载均衡：单AP接入终端超过阈值，引导终端切换邻近AP。
4. 频谱导航，优先引导终端连接5GHz频段。

## 5 安全体系逻辑设计

### 5.1 边界安全逻辑
1. 防火墙划分Trust内网、Untrust外网、DMZ服务器区。
2. 域间策略默认拒绝，最小权限原则，按需开放访问。
3. 开启IPS入侵防御、防病毒、DDoS防护。
4. 源NAT，隐藏内网网段。

### 5.2 内网安全逻辑
1. VLAN二层隔离，不同楼栋VLAN二层不能直接互通。
2. 核心配置ACL，控制楼栋之间、片区之间互访，默认禁止跨楼栋互访，按需放开。
3. 接入交换机端口安全，限制端口最大MAC数量，禁止私接家用路由器。
4. DHCP‑Snooping，ARP网关防护，抵御内网ARP欺骗。

### 5.3 接入安全逻辑
1. 无线Portal + Radius实名认证。
2. SSID连接后强制跳转Portal页面，输入学号密码认证。
3. 对接校园统一身份账号。
4. 支持黑名单封禁违规终端，特殊设备配置MAC白名单免认证。

### 5.4 认证逻辑
1. 终端连接SSID，访问网页被重定向Portal页面。
2. 用户账号密码提交Radius服务器校验。
3. 认证通过，AC放通终端上网权限。
4. 认证日志留存≥6个月，满足等保审计要求。

## 6 QoS逻辑设计

### 6.1 业务优先级划分（由高到低）
1. 最高优先级：网管报文、认证报文、语音会议。
2. 高优先级：网页浏览、在线网课学习。
3. 普通优先级：短视频、社交软件、普通下载。
4. 低优先级：P2P大文件下载、BT下载。

### 6.2 带宽管控机制
1. 单学生终端限速：上行2Mbps，下行20Mbps。
2. 四大片区按在线终端数量比例分配出口总带宽。
3. 拥塞时高优先级优先转发，低优先级报文丢弃限流。
4. 晚高峰20:00‑23:00，对P2P类应用加强限流。
